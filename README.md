# Практическая работа № 2

Конфигурационное управление. Вариант 17. Go.
Инструмент визуализации зависимостей npm-пакетов.

## Этапы

1. JSON-конфигурация, проверка параметров и вывод настроек — готово.
2. Получение прямых зависимостей заданной версии npm-пакета.
3. Граф: рекурсивный DFS, глубина, фильтр, циклы и тестовый репозиторий.
4. Порядок загрузки зависимостей и сравнение с npm.
5. Graphviz, SVG и примеры для трёх пакетов.

## Запуск

Нужен Go 1.22 или новее. Сторонних Go-библиотек нет.

```sh
./run.sh
./run.sh --config configs/test.json
./run.sh --test
```

Windows: `run.bat`, `run.bat --config configs/test.json`, `run.bat --test`.
В терминале VS Code используйте те же команды.
Без скрипта: `go run ./src --config configs/example.json`.
Сборка: `go build -o bin/npm-graph ./src`, тесты: `go test ./...`.

## Настройки JSON

Все семь полей обязательны. `--config` выбирает только файл настроек.

| Поле | Что задаёт |
| --- | --- |
| `package` | Имя npm-пакета, например `express` или `@scope/name`; в тестовом режиме — `A`, `B`, `ABC`. |
| `repository` | URL реестра npm; в тестовом режиме — путь к существующему читаемому файлу. |
| `test_mode` | `true` — тестовый репозиторий, `false` — npm. |
| `version` | Точная версия `X.Y.Z`, допускаются prerelease и build; не диапазон и не `latest`. |
| `output` | Имя будущего `.svg`-файла; родительский каталог должен существовать. |
| `max_depth` | Целое число от 0; 0 означает только корневой пакет. |
| `filter` | Подстрока для исключения пакетов; пустая строка отключает фильтр. |

Пути внутри JSON отсчитываются от папки этого JSON. При выводе сохраняется заданный путь.
`null`, пропущенные и неизвестные поля, неверные типы отклоняются.

## Функции

| Функция | Назначение |
| --- | --- |
| `main` | Запускает приложение и передаёт ОС код завершения. |
| `app.Run` | Обрабатывает `--config`, справку, ошибки и вывод результата. |
| `config.Load` | Читает JSON, проверяет типы и вызывает проверку значений. |
| `Config.Print` | Выводит все семь параметров в формате `ключ=значение`. |
| `checkFields` | Проверяет наличие полей, `null` и неизвестные ключи. |
| `resolvePath` | Разрешает относительные пути от папки конфигурации. |
| `Config.validate` | Объединяет проверки параметров, глубины и фильтра. |
| `Config.validatePackage` | Проверяет имя npm-пакета или тестового пакета. |
| `validVersion` | Проверяет точную версию, включая prerelease и build. |
| `Config.validateRepository` | Выбирает проверку URL или тестового файла. |
| `validateURL` | Проверяет формат HTTP/HTTPS-адреса. |
| `readableFile` | Проверяет существование и читаемость обычного файла. |
| `validateOutput` | Проверяет расширение SVG и каталог назначения. |

## Базовая проверка этапа 1

- `./run.sh` — семь строк `ключ=значение` для `express`.
- `./run.sh --config configs/test.json` — настройки тестового пакета `A`.
- `./run.sh --config configs/invalid/package.json` — ошибка имени пакета.
- Аналогично проверьте `repository.json`, `test_mode.json`, `version.json`,
  `output.json`, `max_depth.json`, `filter.json` в `configs/invalid`.
- `./run.sh --config missing.json` — ошибка отсутствующего файла.
- `./run.sh --help` — справка.

Ошибки выводятся в stderr, код завершения приложения — 1, при успехе — 0.
На первом этапе сеть не используется, граф не строится и SVG ещё не создаётся.
`examples/repository.json` — заготовка для будущего тестового режима: пакет → зависимости.

Формат npm: [документация package.json](https://docs.npmjs.com/cli/configuring-npm/package-json/).
