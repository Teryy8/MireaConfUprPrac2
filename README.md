# Практическая работа № 2. Вариант 17

## Этап 1. Настройки

- Программа на Go, настройки читаются из JSON.
- Проверяются обязательные поля, типы и значения.
- На первом этапе параметры выводились в формате `ключ=значение`.

Настройки в `configs/example.json`:

| Поле | Значение |
| --- | --- |
| `package` | Имя пакета. |
| `repository` | URL реестра npm или путь к тестовому JSON. |
| `test_mode` | `false` — npm, `true` — тестовый файл (с этапа 3). |
| `version` | Точная версия пакета, например `4.18.2`. |
| `output` | Имя SVG-файла для этапа 5. Каталог должен существовать. |
| `max_depth` | Глубина обхода для этапа 3; 0 — только корень. |
| `filter` | Подстрока в имени исключаемого пакета; пустая строка — без фильтра. |

Все поля обязательны. Пути в JSON задаются относительно этого файла.
Примеры ошибок для каждого поля находятся в `configs/invalid`.

Нужен Go 1.22+. Запуск и тесты из папки проекта:

```sh
./run.sh
./run.sh --config configs/example.json
./run.sh --test
```

На Windows: `run.bat`, `run.bat --config configs/example.json`, `run.bat --test`.
Без скрипта: `go run ./src`, тесты: `go test ./...`.
Сборка: `go build -o bin/npm-graph ./src`;
на Windows: `go build -o bin/npm-graph.exe ./src`.
Ошибка: `./run.sh --config configs/invalid/package.json`. Справка: `./run.sh --help`.

## Этап 2. Прямые зависимости

- HTTP-запрос к npm registry, разбор JSON средствами Go. npm и Node.js не нужны.
- Получение зависимостей заданной версии: `dependencies` и `optionalDependencies`.
- При совпадении имён приоритет у `optionalDependencies`. Dev- и peer-зависимости не включены.
- Вывод в алфавитном порядке. Обрабатываются ошибки сети, HTTP и JSON.

Проверки:

```sh
./run.sh                                      # express@4.18.2
./run.sh --config configs/no-deps.json         # lodash, нет зависимостей
./run.sh --config configs/scoped.json          # @babel/code-frame
./run.sh --config configs/not-found.json       # отсутствующая версия, HTTP 404
```

Для npm нужен интернет. Таймаут — 15 секунд, лимит ответа — 16 МиБ.
Ошибки выводятся в stderr с кодом 1, успешный запуск возвращает 0.
Автотесты используют локальный HTTP-сервер и работают без интернета.
