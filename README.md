# Практическая работа № 2

Конфигурационное управление. Вариант 17. Go.
Инструмент визуализации зависимостей npm-пакетов.

## Этапы

1. JSON-конфигурация, проверка параметров и вывод настроек — готово.
2. Получение и вывод прямых зависимостей заданной версии npm-пакета — готово.
3. Граф: рекурсивный DFS, глубина, фильтр, циклы и тестовый репозиторий.
4. Порядок загрузки зависимостей и сравнение с npm.
5. Graphviz, SVG и примеры для трёх пакетов.

## Запуск

Нужен Go 1.22 или новее. Сторонних Go-библиотек нет, npm и Node.js не требуются.
Для реального реестра нужен доступ в интернет.

```sh
./run.sh                         # express версии 4.18.2
./run.sh --config configs/scoped.json
./run.sh --config configs/no-deps.json
./run.sh --test
```

Windows: `run.bat`, `run.bat --config configs/scoped.json`, `run.bat --test`.
В терминале VS Code используйте те же команды.
Без скрипта: `go run ./src --config configs/example.json`.
Сборка: `go build -o bin/npm-graph ./src`, тесты: `go test ./...`.
После сборки: `./bin/npm-graph --config configs/example.json`;
на Windows: `bin\npm-graph.exe --config configs/example.json` (сборка с `-o bin/npm-graph.exe`).

## Настройки JSON

Все семь полей обязательны. `--config` выбирает только файл настроек.
Пример — `configs/example.json`.

| Поле | Что задаёт |
| --- | --- |
| `package` | Имя npm-пакета, например `express` или `@scope/name`. |
| `repository` | URL npm-совместимого реестра, по умолчанию в примере `https://registry.npmjs.org`. |
| `test_mode` | `false` — npm; режим `true` с локальным файлом будет реализован на этапе 3. |
| `version` | Точная версия `X.Y.Z`, допускаются prerelease и build; не диапазон и не `latest`. |
| `output` | Имя будущего `.svg`-файла; родительский каталог должен существовать. Используется с этапа 5. |
| `max_depth` | Целое число от 0; 0 означает только корневой пакет. Используется с этапа 3. |
| `filter` | Подстрока для исключения пакетов, пустая строка отключает фильтр. Используется с этапа 3. |

Пути внутри JSON отсчитываются от папки этого JSON.
`null`, пропущенные и неизвестные поля, неверные типы отклоняются.
В будущем тестовом режиме имя пакета — большие латинские буквы (`A`, `B`, `ABC`),
а `repository` — читаемый файл. Пример подготовлен в `configs/test.json`;
на этапе 2 запуск с ним возвращает понятное сообщение о недоступном режиме.

## Получение зависимостей

Программа выполняет `GET /{package}/{version}` к указанному реестру
и сама разбирает JSON стандартными средствами Go. npm и готовые библиотеки
для получения зависимостей не используются.

Выводятся `dependencies` и `optionalDependencies`, в алфавитном порядке.
При совпадении имён условие из `optionalDependencies` имеет приоритет.
`devDependencies` и `peerDependencies` в список не включаются.
Условия версий (`^`, `~`, диапазоны, URL и т. п.) сохраняются как в реестре;
на этом этапе версии зависимостей не подбираются, вложенные зависимости не запрашиваются.
Таймаут запроса — 15 секунд, размер ответа ограничен 16 МиБ.

Пример начала вывода:

```text
Прямые зависимости express@4.18.2:
  accepts: ~1.3.8
  array-flatten: 1.1.1
  body-parser: 1.20.1
```

Вывод всех параметров относился только к этапу 1 (коммит `93caba7`).
Текущая версия выводит прямые зависимости. Граф и SVG пока не создаются.

## Базовая проверка

- `./run.sh` — прямые зависимости `express@4.18.2`.
- `./run.sh --config configs/no-deps.json` — `lodash@4.17.21`, нет зависимостей.
- `./run.sh --config configs/scoped.json` — зависимости `@babel/code-frame@7.24.7`.
- `./run.sh --config configs/not-found.json` — ошибка HTTP 404 для отсутствующей версии.
- `./run.sh --config configs/invalid/package.json` — ошибка имени пакета.
- Аналогично проверьте `repository.json`, `test_mode.json`, `version.json`,
  `output.json`, `max_depth.json`, `filter.json` в `configs/invalid`.
- `./run.sh --config missing.json` — ошибка отсутствующего файла.
- `./run.sh --help` — справка.

Ошибки выводятся в stderr, код завершения приложения — 1, при успехе — 0.
Тесты работают без интернета: HTTP-реестр поднимается локально через `httptest`.
Проверяются настройки, выбор версии, scoped-имена, сортировка, optional-зависимости,
пустой список, ошибки HTTP/JSON, сети, чтения ответа и таймаут.

## Функции

| Функция | Назначение |
| --- | --- |
| `main` | Запускает приложение и передаёт ОС код завершения. |
| `app.Run` | Обрабатывает `--config`, справку и ошибки. |
| `runAnalysis` | Связывает настройки с запросом и выводом зависимостей. |
| `config.Load` | Читает JSON, проверяет типы и вызывает проверку значений. |
| `checkFields` | Проверяет наличие полей, `null` и неизвестные ключи. |
| `resolvePath` | Разрешает относительные пути от папки конфигурации. |
| `Config.validate` | Объединяет проверки параметров, глубины и фильтра. |
| `Config.validatePackage` | Проверяет имя npm-пакета или тестового пакета. |
| `validVersion` | Проверяет точную версию, включая prerelease и build. |
| `Config.validateRepository` | Выбирает проверку URL или тестового файла. |
| `validateURL` | Проверяет формат HTTP/HTTPS-адреса. |
| `readableFile` | Проверяет существование и читаемость обычного файла. |
| `validateOutput` | Проверяет расширение SVG и каталог назначения. |
| `npm.NewClient` | Создаёт HTTP-клиент реестра с таймаутом. |
| `Client.Dependencies` | Запрашивает метаданные указанной версии и обрабатывает сетевые ошибки. |
| `parseManifest` | Проверяет JSON-метаданные и формирует отсортированный список зависимостей. |
| `npm.Print` | Выводит список или сообщение об отсутствии зависимостей. |

Документация формата: [npm package.json](https://docs.npmjs.com/cli/configuring-npm/package-json/),
[API реестра npm](https://github.com/npm/registry/blob/main/docs/REGISTRY-API.md).
